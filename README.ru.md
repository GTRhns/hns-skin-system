# HNS Skin System · Официальный релиз v1.0

> Counter-Strike 1.6 / AMX Mod X · система пользовательских скинов на базе MySQL, создана для серверов **GTR HNS (Hide & Seek)**.

![Аватар автора](assets/avatar.jpg)

## 1. Что это

**HNS Skin System v1.0 (официальный релиз)** — это полностью переработанная, открытая версия серии плагинов `HnsSkin`, а также **первый официальный стабильный выпуск** серии. Старая система, разрозненная и зависимая от локальных файлов, полностью переписана:

- ✅ **MySQL** — использует свою отдельную базу данных (по умолчанию `skins`), не общую с другими плагинами; подключение настраивается в `configs/mixsystem/skinsql.cfg`
- ✅ **Безлимитные скины** — добавляйте сколько угодно; жёсткого лимита нет (ограничение только на прекэш моделей сервером)
- ✅ **Аренда + навсегда** — покупка даёт **аренду на 30 дней** (настраивается); можно повысить до «навсегда» за монеты (по умолчанию **2000**, настраивается); **админ выдаёт скины навсегда**
- ✅ **Секции TT / CT** — конфиг разделён по командам
- ✅ **Звук смерти на скин** — у каждого скина свой звук смерти (можно переиспользовать)
- ✅ **Экономика ICGB** — переиспользует ваши монеты (`hns_gc_get_player` / `hns_gc_set_player`)

## 2. Происхождение

Система родилась из нужд серверов **GTR HNS (прятки)**. В HNS модель (скин) игрока — ключевая часть индивидуальности, поэтому сначала был создан плагин на локальных файлах (см. архив `versions/`: HnsSkin v1.0.0 → v3.0.2, match-skin-v5 и др.).

Проблемы старой версии:

1. Данные скинов и покупок — в локальных файлах: нет синхронизации между серверами, нельзя посмотреть в админ-панели;
2. Добавление скина требовало правки исходников или сложного конфига;
3. Не было понятия «аренда / навсегда» — либо навсегда, либо никак.

**v1.0** решает всё: MySQL, конфиг без правки кода, трёхуровневая схема «аренда 30 дней + повышение за монеты + выдача админом навсегда», безлимитное добавление скинов. Репозиторий перезапущен как **новый официальный v1.0**.

## 3. Возможности

### 3.1 Аренда и «навсегда»
- Покупка скина за ICGB-монеты = **аренда на `rent_days` дней** (по умолчанию 30, настраивается)
- По истечении срока скин **автоматически теряет силу**, можно **купить снова** (цена та же, срок обновляется)
- Арендный скин можно повысить через меню `/skin` → **«Сделать навсегда»** за **`upgrade_price`** монет (по умолчанию 2000, настраивается)
- **Выдача админом = навсегда**: меню `/cpm` пишет `expire_at = 0`; если у игрока уже есть аренда этого скина — она сразу становится вечной
- В меню показывается статус: `[навсегда]` / `[осталось X дн.]` / `[просрочен]`

### 3.2 Данные в MySQL
- Использует свою отдельную базу данных (по умолчанию `skins`, читает `mixsystem/skinsql.cfg`), не общую с другими плагинами
- 3 таблицы с префиксом `cpm_`: пул скинов / владение игроков / текущий выбор
- В phpMyAdmin видно, у кого какие скины, какие вечные, какие скоро истекают
- Плагин сам создаёт таблицы и сам добавляет колонку `expire_at` в старую базу

### 3.3 Безлимитные скины
- Добавление скина = две строки в `skins.cfg` в секции своей команды, **без лимита**
- Скин = имя + путь к модели + цена + (опционально) звук смерти
- Имя — уникальный ключ, можно на русском/китайском; секции TT / CT

### 3.4 Разделение по командам
- Игрок за T видит/покупает только T-скины; за C — только C-скины
- Без покупки — стандартная модель

### 3.5 Команды
| Команда | Права | Описание |
|---|---|---|
| `/skin` | все | выбрать / купить / повысить скин своей команды |
| `/cpm` | ADMIN_RCON | меню админа: пул / владение / выдать (навсегда) / снять |

## 4. Установка

### 4.1 База данных
1. Выполнить [`sql/hns_skins.sql`](sql/hns_skins.sql) в MySQL (создаст **отдельную базу `skins`** и 3 таблицы).
2. **Для старой базы** (если `cpm_player_skins` уже существует):
   ```sql
   ALTER TABLE cpm_player_skins ADD COLUMN expire_at INT NOT NULL DEFAULT 0;
   ```
   (Плагин сделает это сам при старте, но лучше выполнить вручную)

### 4.2 Плагины
1. Скопировать папку `addons/` в `addons/` сервера (слить с существующей).
2. В `configs/plugins.ini` `CustomPlayerModelsApi.amxx` должен идти **до** `HnsMatchSkin.amxx`.
3. Соединение с БД — из `mixsystem/skinsql.cfg` (отдельная база системы скинов, не общая с другими плагинами).

### 4.3 Конфиг скинов
`addons/amxmodx/configs/mixsystem/skins.cfg`:

```
[SETTINGS]
rent_days  30       ; дней аренды, 0 = сразу навсегда
upgrade_price 2000  ; цена повышения до «навсегда» (монеты ICGB)

[TT]
; имя    путь модели            цена
ЛиНа    models/ddsct/ddsct.mdl  300
        wav misc/ddsct.wav          ; необязательно: звук смерти для скина выше

[CT]
АМин    models/ddsct/ddsct.mdl  300
        wav misc/ddsct.wav
```

После изменений — **смена карты или рестарт**.

## 5. Таблицы БД

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `cpm_skins` | пул скинов | `model_key` (уникальное имя), `model_path`, `price`, `team` T/C, `death_snd` |
| `cpm_player_skins` | владение игроков | `authid`+`model_key` (PK), `bought_at`, **`expire_at` (0 = навсегда)** |
| `cpm_player_current` | текущий выбор | `authid` + `team`, выбранный скин |

Примеры запросов:
```sql
SELECT * FROM cpm_player_skins;                             -- все владения
SELECT * FROM cpm_player_skins WHERE expire_at=0;           -- все вечные
SELECT * FROM cpm_player_skins WHERE expire_at>0;           -- все арендные
SELECT * FROM cpm_player_skins WHERE authid='STEAM_0:1:123'; -- один игрок
```

## 7. Расширение

### 7.1 Добавить скин (частое)
В секции `[TT]` или `[CT]` две строки:
```
имя  путь модели  цена
wav  путь звука   (необязательно)
```
Имя уникально на сервере и его нельзя менять позже (потеряются покупки). Модель должна существовать.

### 7.2 Изменить экономику
Только `[SETTINGS]`:
```
rent_days 30        ; 7 = неделя, 0 = сразу навсегда
upgrade_price 2000  ; цена повышения
```

### 7.3 Скин напрямую через БД
Одна строка в `cpm_skins` (эквивалент конфига), удобно для массового добавления:
```sql
INSERT INTO cpm_skins (model_key, model_path, price, team, death_snd) VALUES ('имя','models/x/x.mdl',300,'T','misc/x.wav');
```

### 7.4 Точки расширения в коде
- Монеты: `hns_gc_get_player(id)` / `hns_gc_set_player(id, n)` (`hns_gc.inc`) — меняйте на свою валюту в этих местах
- Движок отображения: `CustomPlayerModelsApi` (`custom_player_models.inc`) — прекэш моделей и показ клиенту
- Права: поле `pool_flags` пула скинов (`IsAllowed()`)
- Новые команды/режимы: расширяйте перечисление `pool_e` и логику меню

## 8. FAQ

**Плагин не находит таблицу `cpm_player_skins`?**
→ Выполните `sql/hns_skins.sql`; для старой базы — ALTER выше.

**Игрок купил, но скин не виден?**
→ Проверьте порядок в `plugins.ini`: `CustomPlayerModelsApi.amxx` до `HnsMatchSkin.amxx`, оба в `plugins/`.

**Новые скины не появились после смены карты?**
→ Импорт происходит при старте/смене карты — конфиг изменён, карта/рестарт обязательны.

**Как изменить срок/цену?**
→ `[SETTINGS]` в `skins.cfg`, затем смена карты.

**Старые данные сохранятся?**
→ Данные старой локальной версии не мигрируются; новая база стартует с нуля. Все старые версии — в `versions/`.
