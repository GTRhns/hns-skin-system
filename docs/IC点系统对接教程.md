# IC 点系统对接教程 — 零基础也能接

> 面向：**任何想在服务器里"打完比赛自动发积分"的玩家 / 服主 / 开发者**
> 前提：**不需要会写代码**。本文从"插插头"讲起，一步步带你接到任意比赛规则上。
> 适用插件：`HnsICPointMenu.amxx`（v2.0.0，完全独立版，皮肤系统 DLC）

---

## 一、先别怕"接口"两个字

很多同学一听到"接口""对接""native"就头大，觉得自己不会写代码就接不了。先给你吃颗定心丸：

> **对接 IC 点系统，本质上就是"插插头"，和给手机充电是一回事。**

用充电器来打比方：手机上有充电口，充电器上有插头。两者形状不一样没关系，只要**插头规格对得上**，插进去电就通了。你的比赛系统（比如"谁赢谁加分"）就是手机，IC 点系统就是充电器。

IC 点系统早已把"插口"准备好了，**一共就两个**：

| 插口 | 写法 | 意思 |
|------|------|------|
| ① 加积分 | `ic_add_points(id, 数量)` | 给某个玩家加多少分（最常用） |
| ② 查积分 | `ic_get_points(id)` | 查某个玩家现在有多少分（偶尔用） |

**整篇文章的核心，就是教会你：在什么时候、用哪句话，把积分配给玩家。** 学会了这个，你就掌握了接口的全部。

### 为什么只有两个插口就够了？

IC 点系统把"管钱"（记分、扣分、存盘、兑换皮肤）**全部替你做好了**。你只需要告诉它"给谁、加多少"，剩下的它自己搞定。所以对接你的人，永远只用得到这两个插口。

## 二、先看清全景：你接在哪里

动手之前，先花两分钟看清你的服务器里，IC 点系统、你的比赛系统、玩家三者是怎么"排排站"的：

```
玩家在服务器里
   │
   ├── 按 N 键 ──► IC 点系统（HnsICPointMenu）
   │                     │
   │                     ├── 记分 + 存盘 ──► nvault 数据库
   │                     └── 积分够了就兑换 ──► 皮肤模型
   │
   └── 打比赛 ──► 你的比赛系统（判断"谁该得分"）
                        │
                        └── 调用 ic_add_points(id, 分) ──► IC 点系统
```

**一句话记住分工：**

- `你的比赛系统` = **裁判**，负责"判断谁赢"
- `IC 点系统` = **账房**，负责"记分、扣分、存钱、换东西"

裁判只需朝账房喊一句"给某某加 10 分"，账房就麻利地办好了。

**最重要的是：IC 点系统完全独立，它不依赖你的比赛系统。** 哪怕你没有任何比赛系统，IC 点照样能自己跑（管理员手动加分、玩家按 N 键兑换皮肤）。只有当你想"打完比赛自动加分"时，才需要把自己接上去。

## 三、三条路，选一条适合你的

根据你的技术水平，有三条完全不同的路可以走。按"省心程度"排好队，你挑最舒服的那条：

| 路 | 适合谁 | 要改的东西 | 效果 |
|----|--------|-----------|------|
| **路 A** · 零代码 | 完全不想碰代码 | 什么都不改 | 管理员手动给玩家 / 全体玩家加分 |
| **路 B** · 半自动 | 会复制文件、敢加一行 | 复制 1 个头文件 + 加 1 行 include | 你的插件能调用 IC 点接口 |
| **路 C** · 全自动 | 想要"打完自动加分" | 在比赛系统源码加 2~3 行调用 | 例如"赢家 +10、输家 +5"，全自动 |

**建议新手从路 A 开始**，先看到积分真的能加上去，建立信心；再决定要不要走向路 C。

---

## 四、路 A：管理员手动加分（零代码）

这是最快的验证方式。IC 点系统**自带管理员加分命令，你不需要改任何代码，只需要有管理员权限**。

> **前提**：你的账号必须写在服务器的 `users.ini` 里（官方认证管理员）。IC 点系统只认这种管理员，其它渠道的假管理权限一律无效——这是防止别人乱扣分的安全设计。

**给单个玩家加分**（游戏里按 `Y` 打开聊天框）：

```
/givetic 小明 10
```

名字可以只打一部分，能认出来就行。

**给在线所有玩家加分**（适合活动派发）：

```
/givetic @ALL 50
```

也可以换成 `/giveic` 或 `/addic`，三个命令效果一样，看你哪个顺手。

> **验证成功长什么样**：加分成功后，玩家屏幕上会弹出一行彩色提示 `[IC点] 获得+10分 (当前…)`。看到这行字，就说明 IC 点系统跑通了。

想让玩家自己看积分、兑换皮肤？告诉玩家按 **N 键**（或聊天框输入 `/ic`）就能打开 IC 菜单。人物皮肤 500 分、刀皮肤 300 分，都可以在服务器配置里改（`ic_skin_person` / `ic_skin_knife`）。

## 五、路 B：让插件"认识"IC 点系统

如果你有某个比赛插件（比如每局结束自动处理），想让它以后能调用 IC 点接口，先做这一步"接线"。这一步**不写业务逻辑，只是让两边认识和握手**。

### 第 1 步：把"插头"放进工具箱

IC 点系统附赠了一个头文件 `ic_points.inc`，它就是你比赛系统要用的"插头"。把它复制到你的 AMXX 编译目录的 include 文件夹里：

```
cstrike/addons/amxmodx/scripting/include/ic_points.inc
```

（和 `amxmodx.inc` 等放在一起）

### 第 2 步：在源码顶部加一行"声明"

打开你比赛系统的源码文件（后缀是 `.sma`），在最上面那一堆 `#include` 的后面，加这一行：

```pawn
#include <ic_points>
```

加完这行，你的插件就"认识"IC 点系统的两个插口了，编译时也不会报"找不到函数"。

> **还没有 .sma 源码？** 想要写代码对接，你必须有自己比赛系统的源码文件（.sma）。如果只有编译好的 .amxx，那只能走路 A。源码就好比"说明书"，没有它就没法在里面加字。

> **加载顺序要记住**：服务器上，**IC 点系统必须先加载、你的比赛系统后加载**。因为要先有"账房"站在那儿，裁判才能喊它。在 `plugins.ini` 里，把 `HnsICPointMenu.amxx` 这行写在你的比赛插件**上面**。加反了会报接口找不到。

## 六、路 C：真正写代码对接（完整示例）

走到这一步，你已经完成了"接线"（路 B）。现在要做的，就是**在"玩家结束比赛"的时刻，喊账房一句"给谁加多少分"**。

### 完整示例：赢家 +10 分，输家 +5 分

假设你的比赛系统在每局结束时，调用了一个函数 `RoundEnd(winner)`，里面的 `winner` 就是赢家玩家。你在里面加上几行调用：

```pawn
// 这是你比赛系统源码里的一个函数，"每局结束"时会被调用
public RoundEnd(winner) {
    // ---- 以下高亮行是你新加的（其它都是你自己的代码）----
    ic_add_points(winner, 10);      // 赢家 +10 分

    new iLosers[32], iNum;
    get_players(iLosers, iNum, "ch");
    for (new i = 0; i < iNum; i++)
        if (iLosers[i] != winner) ic_add_points(iLosers[i], 5);  // 其它人 +5 分
    // ----------------------------------------------------
}
```

存盘、重新编译、放回服务器。从此只要一局结束，赢家自动 +10、输家自动 +5，**完全不用管理员手动操作**。

### 逐行拆解：这段代码到底在说什么

| 代码 | 人话解释 |
|------|---------|
| `ic_add_points(winner, 10)` | "给 winner 这位玩家加 10 分。" winner 就是赢家的编号，10 就是加的分 |
| `get_players(iLosers, iNum, "ch")` | "把在场所有玩家列出来，一个个看。" |
| `for (i...) if (iLosers[i] != winner) ic_add_points(iLosers[i], 5)` | "除了赢家，给每个其它玩家 +5 分。" |

> **"id"这个词不用怕**：代码里的 `id`（比如 `winner`）不是玩家名字，而是玩家在服务器里的"座位号"。你不用自己算它——你的比赛系统在"玩家进服""玩家胜利"等时刻，会自动把这个座位号递给你。你只管把它原样传给 `ic_add_points` 就行。

## 七、接口速查表（收藏这张就够了）

把下面这张表当成你的"小抄"。以后想加积分、查积分，回来翻一眼就行。

| 插口 | 写法 | 参数解释 | 返回什么 |
|------|------|---------|---------|
| 加积分 | `ic_add_points(id, 数量)` | `id`=玩家座位号；`数量`=要加的正整数 | 成功返回 `1`，失败返回 `0` |
| 查积分 | `ic_get_points(id)` | `id`=玩家座位号 | 返回该玩家当前积分数 |

### 唯一要守的规矩

> 加分的"数量"**必须是正数**。想扣分？不要用负数。
>
> IC 点系统只认"加"这个动作，扣分它不管——这是刻意的安全设计，防止有人写出能随便扣别人积分的漏洞。如果你确实需要扣分逻辑，请在你的比赛系统里**先判断"分数够不够"，再决定加多少**。

## 八、常见问题自查

| 现象 | 原因 | 解决办法 |
|------|------|---------|
| 编译报"找不到 ic_add_points" | 没加 `#include <ic_points>`，或头文件没复制对位置 | 确认 `ic_points.inc` 已在 include 目录，源码顶部有 include |
| 游戏里提示"接口找不到" | IC 点插件加载顺序在比赛插件之后 | 把 `HnsICPointMenu.amxx` 在 plugins.ini 里排到最前面 |
| 积分没加上，也没报错 | 传的 `id` 不是有效玩家，或数量 ≤ 0 | 检查 id 是否来自连接玩家的回调；数量用正数 |
| 管理员加分被拒 | 账号不在 `users.ini` 认证名单 | 把账号写进 users.ini 获得官方管理权限 |

## 九、回顾：你其实学会了全部

- **接口不可怕** —— 就是"插插头"，一共两个插口：加积分、查积分。
- **分工很清晰** —— 你的比赛系统当裁判管"判断"，IC 点系统当账房管"记分"。
- **三条路随你选** —— 零代码用 `/givetic`；敢加一行就走 include；想全自动就在比赛结束处写两行调用。
- **发分时机由你定** —— 赢家 +10、输家 +5、参与就 +1，全看你自己的规则，IC 点系统不替你决定。

> **给你的下一步建议**：先把路 A 跑通，看到积分真的加上去了；再决定要不要升级到路 C。如果卡在任何一步，把你看到的**报错原文**发到 Issues，我帮你逐字排查。

**最后送你们一句：对接的本质不是写代码，而是想清楚"什么时候、给谁、加多少"。这个想明白了，代码只是顺手的事。**
